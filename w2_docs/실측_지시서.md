|---|---|---|---|

| S7 | `tests/smoke_a2.py` | `w2_result_thur`에서만 통과하면 됨. motor DR event가 추가된 상태로 통과하는지 | M2-0 |

S3 (a)를 가장 먼저 확인할 것. `w2_result_thur` 작업 트리에서:

60·120·180분 시점 기록
- 시작 시각을 적고, 60·120·180분 즈음 콘솔의 `Learning iteration X/Y`와 아래 값을 표에 적음 (wandb의 `Train/mean_reward/time`은 x축이 학습 시간(초)이라 나중에 다시 읽기 좋음)
  - `Mean reward`, `Mean episode length`
  - `Episode_Reward/track_lin_vel_xy`, `Episode_Reward/track_ang_vel_z` (화요일은 이 둘이 전부)
  - `Curriculum/terrain_levels`, `Curriculum/lin_vel_cmd_levels`
- 그 시점에 가장 가까운 `model_N.pt`(500 iteration마다 저장, V-02)의 N
- 수렴 판단: reward 곡선이 마지막 30분 동안 거의 평평한지. "60분이면 충분 / 120분 필요 / 180분에도 오르는 중" 중 하나로

V-01 결정에 쓸 것: 수업 학습은 11시 시작 15시 끝(최대 4시간). 성현 검증 정책은 10001 iteration. 결과 문서에 "수업용 max_iterations 제안값과 이유"를 적음.

### M3. 화요일 결과의 모습

```bash
cd $EDU/../w2_result_tue
python scripts/rsl_rl/play.py --task $T --load_run '*_w2_tue_full' --num_envs 16
python scripts/rsl_rl/play.py --task $T --load_run '*_w2_tue_full' --num_envs 16 --headless --video --video_length 500
```

- 화요일 policy는 velocity command를 보지 못함 (의도). 화면의 초록·파랑 화살표(command, 실제 속도)를 보며 관찰
- 관찰해서 적을 것
  - 걷는가, 서 있는가, 제자리 걸음인가, 한 방향으로만 가는가
  - command가 바뀌어도(10초마다) 움직임이 바뀌는가
  - 쓰러지는가, 지형(계단·경사)에서는 어떤가
  - `track_lin_vel_xy` 곡선이 어느 값에서 멈췄는가 (평균 command 쪽으로 걷는 정책이면 중간값에서 멈춤)
  - "command를 못 보니 추종을 못 한다"로 설명되는 실패인지, 다른 이유가 보이는지
- 영상은 `logs/rsl_rl/a2_base_rl/<run>/videos/play/`에 생김. 6절 보관 폴더로 복사 (V-204)

## 4. 코드를 고칠 때

- 고치는 곳은 그 코드가 처음 생기는 가장 아래 브랜치
  - 힌트 주석, 점검 스크립트, `randomize_actuator_gains`의 제공 줄(`kp0 =` 등), curriculum 보호 줄: `w2_edu`
  - 정답 줄: 그 요일 result 브랜치 (화 정답 → `w2_result_tue`)
- 고친 뒤 위 브랜치로 차례로 merge하고 push (force push 금지)

```bash
cd $EDU/../w2_edu && git commit -am "w2 실습: <무엇을 고쳤는지>" && git push origin w2_edu
cd ../w2_result_tue  && git merge w2_edu         && git push origin w2_result_tue
cd ../w2_result_wed  && git merge w2_result_tue  && git push origin w2_result_wed
cd ../w2_result_thur && git merge w2_result_wed  && git push origin w2_result_thur
```

- 고친 구역마다 `# 2611DD hw: 주제` 주석 (DD = 고친 날, 예: `# 261121 hw: w2 실습 motor DR 기본 gain`)
- 커밋 메시지에 Claude 표시 줄(Co-Authored-By 등)을 넣지 않음
- `main`, `old/*`, `shlim/a2_sim2real_dev`는 건드리지 않음
- 고친 내용은 `실측_결과.md`의 "코드 변경 내역"에 브랜치, 파일, 이유, 커밋 해시로 적음. Windows PC에서 브랜치 생성 원본(`2주차_자료/브랜치_제작/template/`)을 이 내역대로 맞춤
- 줄 번호가 바뀌는 수정이면 결과 문서에 "줄 번호 바뀜"이라고 적음 (Windows PC에서 `make_variables.py`로 V-100번대를 다시 만듦)
