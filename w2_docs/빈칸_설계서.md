# 빈칸 설계서 (w2_edu와 result 브랜치)

기준: `origin/shlim/a2_sim2real_dev` (`84d1a91`). 공통 전제는 `00_2주차_제작_계획.md`.
브랜치 제작 세션은 이 문서대로 만들고, 여기서 정하지 않은 세부는 같은 원칙으로 판단함.

## 1. 동작 원칙

| 원칙 | 내용 |
|---|---|
| 스위치는 cfg 등록 | 아직 안 배운 항목은 `a2_env_cfg.py`에 등록 줄이 없음. 등록 줄도 수강생이 작성 |
| 미작성은 큰 소리로 실패 | 빈 함수는 `raise NotImplementedError("w2 화 | 기본-1: base_ang_vel 미작성")`. 0을 조용히 반환하는 자리는 만들지 않음 |
| 빈 상태로도 학습 실행 | `w2_edu` 그대로 `train.py`가 돌아야 함. 이를 위해 아래 "처음부터 제공" 항목만 등록해 둠 |
| 입력 순서 = 등록 순서 | policy obs는 등록 순서대로 이어 붙고 `deploy.yaml`과 같아야 함. 등록 자리를 주석으로 표시 |
| 도전 문제도 학습 항목 (11/19 사용자 확정) | 그날 학습에 들어가는 항목 중 가장 어려운 것을 도전으로 냄. 함수와 등록 줄 모두 수강생이 작성. 11시 학습은 각자의 답으로 돌고, 15시에 정답 확인 |

처음부터 제공하는 항목 (빈 상태 학습에 필요한 최소)

- policy·critic obs의 `last_action`: obs 그룹에 항목이 하나도 없으면 manager 생성에서 오류가 남. 화요일 obs 풀이 예시로 씀
- reward `track_ang_vel_z`: 화요일 reward 풀이 예시로 씀
- `lin_vel_cmd_levels` curriculum에 보호 줄 추가: reward `track_lin_vel_xy`가 아직 등록되지 않았으면 범위를 바꾸지 않고 현재 값을 반환. 화요일 도전 문제가 `track_lin_vel_xy`라서 빈 상태에서는 이 항목이 없음
- scene, terrain, command, action, termination, curriculum, 기존 event(push_robot 제외) 전부

도전 문제를 틀렸거나 못 쓴 경우의 대비

- 점검 스크립트의 성질 검사로 학습 시작 전에 걸러냄 (7절)
- 15시 제어기 테스트는 result 브랜치로 미리 학습한 checkpoint로 진행할 수 있음
- 다음 날 학습 전에 정답으로 고쳐 두므로 오류가 누적되지 않음

## 2. 힌트 주석 형식

- 기존 영어 docstring은 그대로 둠
- 한글 힌트는 본문 주석 블록. 개조식, 변수·필드 이름은 영어 원문, 단계마다 줄바꿈
- 머리 태그: `# [w2 화 | 기본-1]` (요일 | 난이도-번호). 슬라이드가 이 태그로 가리킴
- 정답 줄을 주석으로 숨겨 두지 않음
- result 브랜치에서는 힌트 블록을 그대로 두고 `raise` 줄만 정답으로 바꿈

함수 본문 예 (기본)

```python
def base_ang_vel(env: ManagerBasedEnv, asset_cfg: SceneEntityCfg = SceneEntityCfg("robot")) -> torch.Tensor:
    """Root angular velocity in the asset's root frame."""
    # [w2 화 | 기본-1] 몸체 각속도
    #
    # - 역할: IMU 자이로가 재는 값
    # - 출력: (num_envs, 3), rad/s, body frame
    #
    # 1. 로봇 가져오기
    #    - env.scene[asset_cfg.name]
    # 2. 몸체 각속도 꺼내기
    #    - 위치: asset.data
    #    - 이름 끝 _b = body frame, _w = world frame
    # 3. 그대로 return
    raise NotImplementedError("w2 화 | 기본-1: base_ang_vel 미작성")
```

함수 본문 예 (중간): 수식과 쓸 재료만 주고 단계는 덜 나눔

```python
    # [w2 수 | 중간-1] 에너지 벌점
    #
    # - 수식: sum_j |joint_vel_j| * |torque_j|
    # - 출력: (num_envs,)
    # - 재료: asset.data.joint_vel, asset.data.applied_torque
    #         관절 선택은 [:, asset_cfg.joint_ids]
    raise NotImplementedError("w2 수 | 중간-1: energy 미작성")
```

cfg 등록 자리 예

```python
    class PolicyCfg(ObsGroup):
        # [w2 화 | 기본-5] policy obs 등록
        #
        # - 형식: 이름 = ObsTerm(func=mdp.함수, scale=..., clip=(-100, 100))
        # - 순서: base_ang_vel, projected_gravity, joint_pos_rel, joint_vel_rel, last_action
        #         이 순서가 곧 신경망 입력 순서. deploy.yaml과 같아야 함
        # - scale: base_ang_vel 0.2, joint_vel_rel 0.05, 나머지는 없음
        #
        # (여기에 작성)

        # [w2 수 | 기본-1] velocity_commands는 projected_gravity 바로 다음 자리

        last_action = ObsTerm(func=mdp.last_action, clip=(-100, 100))  # 풀이 예시
```

- 계열의 첫 등록 줄은 완성된 줄을 주석 예시로 보여 주고, 나머지는 weight·params를 힌트 표로 주고 직접 작성
- weight가 곱셈식으로 남은 곳(`-2.5e-7 * 0.5 * 0.5` 등)은 정답 기준 표기를 그대로 둠

## 6. motor DR 사양 (새로 추가)

- 이름: `randomize_actuator_gains` (`mdp/events/randomize_events.py`, `__init__.py`에 export)
- 인자: `asset_cfg`, `stiffness_range`, `damping_range`, `strength_range` (모두 기본값 대비 배율)
- 계산: `kp = kp0 × U(stiffness_range) × s`, `kd = kd0 × U(damping_range) × s`, `s = U(strength_range)`
  - strength를 Kp와 Kd에 같은 배율로 곱하면 PD 출력 토크 전체에 배율을 곱한 것과 같음 (effort limit 적용 전)
  - 매번 기본 gain에서 다시 계산 (누적 금지)
- 대상: `asset.actuators`의 explicit actuator(`DCMotor`)의 `stiffness`, `damping` 텐서 (env × joint)
- 등록: `mode="reset"`, 범위는 보수적으로 Kp (0.9, 1.1), Kd (0.9, 1.1), strength (0.9, 1.1)
- Isaac Lab 2.3.0의 `randomize_actuator_gains`를 참고하되 이 저장소의 `_randomize_prop_by_op`를 재사용할지 여부는 구현 세션이 판단. 실제 동작은 Linux PC에서 확인

## 7. 점검 스크립트

`scripts/w2_check.py --day tue|wed|thur` (headless, 8 env, 1분 안쪽)

- 등록 상태: 그날까지 있어야 할 obs·reward·event 항목과 순서, policy·critic 차원
- 미작성 목록: 등록됐는데 `NotImplementedError`를 내는 함수, 아직 미등록인 항목
- 성질 검사 (정답 코드를 담지 않고 확인)
  - shape와 유한값
  - 벌점 함수는 0 이상, 추종 reward는 0 초과 1 이하
  - 정지 자세에서 `projected_gravity` z가 −1 근처, `joint_pos_rel`이 0 근처
  - 몸체 속도를 command와 같게 써 넣으면 추종 reward가 1 근처
- 도전 항목은 따로 표시: 미작성이어도 학습은 시작되지만 그 항목이 빠진다는 경고를 냄. 도전 함수에도 성질 검사를 적용 (예: `track_lin_vel_xy_exp`는 몸체 속도가 command와 같을 때 1 근처, `feet_air_time`은 command가 0이면 0)
- 출력은 한글 표. 마지막 줄에 "학습 시작 가능" 또는 남은 태그 목록
- `tests/smoke_a2.py`는 `w2_result_thur`에서만 통과하면 됨
